# TG WS Proxy для Android

Порт [tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy) на Android. Ядро протокола не переписано: внутри приложения работает настоящий CPython, исполняющий тот же пакет `proxy/`, что и десктопная версия.

## Как это устроено

```
Telegram для Android
        │  обычный MTProto-прокси на 127.0.0.1:1443
        ▼
приложение TG WS Proxy ── foreground-сервис ──┐
        │                                      │  внутри — CPython (Chaquopy)
        │  разбор obfuscated2, номер DC,        │  и пакет proxy/ без изменений
        │  ре-шифрование, нарезка на пакеты     │
        ▼                                      │
WebSocket поверх TLS, порт 443 ───────────────┘
        ▼
kwsN.web.telegram.org → дата-центр Telegram
```

Это работает потому, что на Android все приложения делят один сетевой namespace: `127.0.0.1` одного приложения виден другому. Telegram подключается к прокси как к обычному MTProto-прокси в интернете — ни VPN, ни root не нужны.

## Требования

| | |
| --- | --- |
| Android | 7.0 и новее (API 24) |
| Архитектура | arm64-v8a |
| Место | около 60 МБ после установки |

**Почему только arm64.** Chaquopy отдаёт нужную версию Python (3.13, ради свежих колёс `cryptography`) лишь для `arm64-v8a` и `x86_64`. Ради 32-битного ARM пришлось бы откатывать Python на несколько версий назад. Практического смысла в этом нет: arm64 — стандарт с 2015 года, а Google Play требует 64-битные сборки с 2019.

## Установка

Скачайте APK со [страницы релизов](https://github.com/Arkomiko/tg-ws-proxy/releases/latest) и установите. Android предупредит об установке из неизвестного источника — приложение не публикуется в Google Play.

## Подключение Telegram

**Автоматически.** Нажмите «Начать», затем «Открыть в Telegram» — он предложит включить прокси.

**Вручную.** Настройки → Данные и память → Настройки прокси → Добавить прокси:

- Тип: **MTProto**
- Сервер: `127.0.0.1`
- Порт: `1443`
- Secret: значение с главного экрана приложения

## Плитка в шторке

Приложение добавляет плитку быстрых настроек рядом с Wi-Fi и фонариком. Короткое нажатие включает и выключает прокси, долгое открывает приложение.

Если плитки нет в шторке — откройте редактор плиток (карандаш) и перетащите её из списка доступных.

## Настройки

Повторяют окно настроек десктопной версии:

| Раздел | Что настраивается |
| --- | --- |
| Интерфейс | язык (русский, английский), тема (авто, светлая, тёмная) |
| Подключение MTProto | IP-адрес, порт, secret |
| Датацентры Telegram | соответствие номера DC и IP, по правилу на строку |
| Cloudflare Proxy | включение и собственные домены |
| Cloudflare Worker | собственные домены |
| Логи и производительность | подробный лог, буфер, размер пула, максимальный размер лога |
| Дополнительно | автозапуск после перезагрузки, тестовые датацентры |

Порт ниже 1024 указать нельзя: на Android такие порты недоступны без root.

## Фоновая работа

Прокси держит слушающий сокет и пул WebSocket-соединений, поэтому работает как foreground-сервис с постоянным уведомлением. Тип сервиса — `specialUse`, а не `dataSync`: у последнего на Android 15 суточный лимит в 6 часов, для постоянно работающего прокси это не годится.

**Прошивки могут усыплять приложение.** Xiaomi, Huawei, Transsion (Infinix, Tecno) и другие делают это агрессивнее стока. Признак: Telegram показывает бесконечное «подключение прокси», а стоит открыть приложение — всё сразу оживает.

Что помогает:

1. Снять ограничения в менеджере питания прошивки — `Phone Master`, «Управление питанием», «Автозапуск»
2. Закрепить карточку приложения в «Недавних»
3. Согласиться на предложение отключить батарейную оптимизацию при первом запуске

Со своей стороны приложение делает что может: удерживает частичный wake lock с продлением, раз в 10 минут будит себя сторожевым будильником, поднимается после перезагрузки и после смахивания из «Недавних», а при смене сети или включении VPN сбрасывает накопленные отказы и пересобирает пул соединений.

## Логи

Кнопка «Открыть логи» на главном экране показывает хвост лога и позволяет его скопировать. Файл лежит в приватном каталоге приложения и ротируется.

Долгое нажатие на блок «Диагностика» выводит полный срез состояния — счётчики, чёрные списки, живость потоков — и записывает его в лог. Это нужно, если прокси выглядит запущенным, но ничего не делает.

## Сборка из исходников

Нужны JDK 17 и Android SDK (platform 35, build-tools 35+), а также Python 3.13 на машине сборки — Chaquopy использует его для установки зависимостей.

```bash
cd android
./gradlew assembleDebug     # отладочная сборка
./gradlew assembleRelease   # релизная
```

Релизная сборка подписывается ключом из `android/keystore.properties`:

```properties
storeFile=/путь/к/keystore.jks
storePassword=...
keyAlias=...
keyPassword=...
```

Файла нет в репозитории. Без него релиз соберётся неподписанным.

**Ядро не копируется в модуль.** Gradle-задача `syncPythonCore` кладёт `proxy/` и часть `utils/` из корня репозитория в `build/pythonCore`, а Chaquopy берёт эту папку как источник Python-кода. Источник истины по протоколу остаётся один.

## Отладка в VS Code

В `.vscode/launch.json` есть три конфигурации для панели «Запуск и отладка»:

| Конфигурация | Действие |
| --- | --- |
| Update to APP | собрать и установить на телефон |
| Build APK | только сборка |
| Reload APP | перезапустить приложение на телефоне |

Пути к JDK и SDK заданы в `.vscode/android.ps1` — поправьте под свою машину.
